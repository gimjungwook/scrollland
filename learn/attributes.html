속성의 공유와 변경 규칙 정하기

모든 관찰 기록의 단위는 마리였습니다. 한 기록만 개체로 표시하면 다른 기록의 단위도 바뀔까요?

first.unit = "개체"→second.unit: "마리"

객체마다 값을 두는 방법을 배웠습니다. 클래스에서 함께 읽는 속성과 개별 객체에 생기는 속성은 조회하는 위치가 다릅니다.

한 객체의 단위만 바뀌는 관계를 보고, 속성을 추가·삭제하거나 property로 변경 규칙을 정하는 방법을 비교합니다.

읽고 나면클래스 속성·인스턴스 속성·캡슐화와 property의 역할을 구별합니다.

먼저 익힐 개념 · 데이터와 행동을 객체로 묶기 · 함수 앞뒤에 공통 작업 붙이기

01

개별 속성을 추가하고 지우기

인스턴스 속성은 각 객체에 붙은 상태입니다. 일반 클래스에서는 생성 뒤 새 속성을 대입할 수 있습니다. hasattr()는 해당 이름의 속성을 읽을 수 있는지 확인합니다.

del record.note는 이 객체의 note 속성을 제거합니다. 객체 전체나 파일을 지우는 지시가 아닙니다. 필요한 필드를 언제나 보장해야 한다면 초기화 단계에서 이름을 정하고 일관되게 유지하세요.

Pythonattributes.py
01class Observation:02    def __init__(self, count):03        self.count = count04 05record = Observation(4)06record.note = "비 온 뒤"07print(record.note)08del record.note09print(hasattr(record, "note"))

공통 값과 개별 값 구별하기

클래스 본문에 둔 속성은 여러 인스턴스가 공통으로 조회할 수 있습니다. 인스턴스에 같은 이름의 속성이 있으면 그 값이 클래스 속성을 가립니다.

여러 객체가 각자 다른 목록을 가져야 할 때 빈 리스트를 클래스 속성으로 두면 하나를 공유하게 됩니다. 개별 목록은 __init__ 안에서 self.items = []처럼 매번 만드세요.

first.unit을 바꾸면 클래스와 second의 단위도 바뀔까요?

03

공개된 변경 경로에 규칙 두기

캡슐화는 내부 상태와 그 상태를 다루는 규칙을 한곳에 묶고 사용할 접근 방법을 정하는 설계입니다. 밑줄 하나로 시작하는 _count는 내부 구현이라는 관례이며 보안 잠금이 아닙니다.

@property 아래의 count 메서드는 record.count를 읽을 때 실행됩니다. @count.setter 아래의 count 메서드는 record.count = 값처럼 대입할 때 실행됩니다. 두 데코레이터는 이름이 같은 두 메서드를 조회와 대입을 담당하는 한 속성에 연결합니다.

raise ValueError(...)는 허용하지 않는 값이라고 알리고 해당 대입을 중단하는 지시입니다. 아래 대입 메서드는 음수가 아닌 값만 _count에 저장합니다. 예외를 받아 사용자에게 응답하는 방법은 「예외를 구별해 처리하기」 레슨에서 다룹니다.

밑줄 두 개로 시작하는 __count 같은 속성 이름에는 클래스 이름을 포함하는 이름 변환이 적용됩니다. 다른 클래스의 이름과 우연히 충돌하는 일을 줄이지만 외부 접근을 완전히 금지하지는 않습니다. 이 예제는 내부 구현임을 나타내는 밑줄 하나의 _count를 사용합니다.

Pythonattributes.py
01class Observation:02    def __init__(self, count):03        self.count = count04    @property05    def count(self):06        return self._count07    @count.setter08    def count(self, value):09        if value < 0:10            raise ValueError("수량은 0 이상이어야 합니다")11        self._count = value12 13record = Observation(4)14record.count = 515print(record.count)

클래스 속성으로 빈 리스트를 두고 여러 인스턴스가 수정하면 어떤 점을 주의해야 하나요?

  1. 각 인스턴스마다 자동으로 복사됩니다.
  2. 같은 리스트를 공유해 다른 인스턴스에서도 변경이 보일 수 있습니다.
  3. 클래스 속성은 수정이 불가능합니다.

답을 떠올린 뒤, 아래의 설명과 비교해 보세요.

정답같은 리스트를 공유해 다른 인스턴스에서도 변경이 보일 수 있습니다.

오답: 각 인스턴스마다 자동으로 복사됩니다.개별 속성이 가리지 않는다면 같은 클래스의 리스트를 공유합니다.

정답: 같은 리스트를 공유해 다른 인스턴스에서도 변경이 보일 수 있습니다.각자 목록이 필요하면 __init__ 안에서 새 리스트를 만드세요.

오답: 클래스 속성은 수정이 불가능합니다.리스트 자체는 변경 가능한 객체입니다.
