프로젝트마다 도구 환경 나누기

같은 컴퓨터의 두 프로젝트가 서로 다른 패키지 버전을 요구합니다. 한쪽 도구를 바꿨을 때 다른 쪽까지 달라지지 않게 하려면요?

with_pip=False로 생성→설정 파일 존재: True

모듈을 불러오는 코드를 배웠습니다. 그 코드가 어느 Python과 설치된 패키지를 사용하는지도 프로젝트별로 구별해야 합니다.

실행 중인 Python을 확인하고 임시 가상 환경을 만듭니다. 환경 생성과 그 환경의 Python으로 실행하는 일을 나누어 읽습니다.

읽고 나면인터프리터·가상 환경·pip의 역할과 실행 경계를 구별합니다.

먼저 익힐 개념 · 처음 실행하고 결과 읽기 · 모듈을 불러와 연결하기

01

같은 컴퓨터, 다른 프로젝트

관찰 기록을 정리하는 프로젝트와 다른 프로젝트가 서로 다른 버전의 패키지를 요구할 수 있습니다. 프로젝트마다 도구 환경을 나누면 어느 Python과 패키지를 쓰는지 구분할 수 있습니다.

이 레슨에서는 환경을 만드는 일과 그 환경의 Python을 선택해 실행하는 일을 구별합니다. 사이트를 읽는 동안 설치나 설정을 할 필요는 없습니다.

02

지금 실행하는 Python 확인하기

같은 .py 파일도 어떤 Python 프로그램으로 실행하느냐에 따라 쓸 수 있는 패키지가 달라집니다. 코드를 읽어 실행하는 이 프로그램을 인터프리터라고 합니다. sys 모듈은 지금 실행 중인 Python의 정보를 알려 줍니다.

sys.version_info에는 버전 숫자가 들어 있습니다. 예제는 그 버전이 3.10 이상인지 비교해 True를 출력하고, major로 큰 버전 번호 3을 출력합니다. 정확한 실행 파일 위치는 sys.executable로 확인할 수 있습니다. 사이트의 내용을 읽기 위해 설치할 필요는 없습니다.

Pythonenvironments.py
01import sys02 03print(sys.version_info >= (3, 10))04print(sys.version_info.major)

실행 결과

True
3
03

설치할 환경과 실행할 Python을 맞추기

가상 환경은 프로젝트마다 사용할 Python 실행 파일과 패키지 설치 위치를 따로 마련한 폴더입니다. pip는 그 Python이 쓸 외부 패키지를 설치하는 도구입니다. 먼저 두 역할을 구별해 보겠습니다.

두 프로젝트가 같은 도구의 서로 다른 버전을 쓴다고 가정하겠습니다. 아래의 “예시 도구 v1·v2”는 차이를 설명하기 위해 붙인 가상 이름과 버전입니다. 실제 패키지를 설치하거나 명령을 실행하는 화면이 아닙니다.

먼저 A와 B의 폴더에 가상 환경을 각각 만듭니다. 다음으로 새 명령에 사용할 Python을 고릅니다. A 환경의 Python으로 pip를 실행하면 A 환경에 설치하고, B 환경의 Python으로 pip를 실행하면 B 환경에 설치합니다.

프로그램도 같은 환경의 Python으로 새로 실행해야 그 환경의 패키지를 씁니다. 이미 실행 중인 Python이 다른 환경으로 바뀌는 것은 아닙니다. 환경을 활성화하는 것은 명령이 찾을 Python을 고르는 편의이며 필수 단계는 아닙니다. 환경 안의 실행 파일 경로를 직접 지정해도 됩니다.

A에 필요한 도구를 설치할 때 B의 버전까지 바뀌지 않게 하려면 무엇을 골라야 할까요?

설치와 실행에 사용할 Python

프로젝트마다 설치 위치를 나누고, 설치할 때와 실행할 때 해당 환경의 Python을 사용합니다.

가상 환경 폴더만 만들었다고 모든 명령이 자동으로 그곳을 사용하지는 않습니다. 패키지 설치와 프로그램 실행에 사용할 Python을 같은 환경에서 골라야 합니다.

import는 이렇게 선택해 시작한 Python에서 모듈을 가져옵니다. 설치를 하거나 실행 중인 프로세스를 다른 환경으로 전환하는 지시가 아닙니다. 아래 참고 예제는 환경 생성 여부만 확인합니다.

04

참고: 임시 폴더에서 환경 생성 확인하기

프로젝트 A와 B가 서로 다른 외부 패키지 버전을 요구하면 설치 위치도 나누어야 합니다. 가상 환경은 프로젝트별 Python 실행 파일과 패키지 설치 위치를 마련한 폴더입니다. 환경을 만드는 일과 그 안의 Python으로 코드를 실행하는 일은 별개입니다.

실제 프로젝트에서는 터미널에 python3 -m venv .venv를 입력해 .venv 폴더를 만듭니다. Windows에서는 py -m venv .venv를 쓸 수 있습니다. 이 명령은 Python 코드의 import 문과 다릅니다. 터미널 명령은 실행할 Python과 작업을 고르고, import는 실행 중인 Python에서 모듈을 가져옵니다.

아래는 프로젝트를 바꾸지 않고 임시 폴더에 환경을 만들어 보는 Python 예제입니다. TemporaryDirectory()로 받은 경로가 folder이고, venv.create(folder, with_pip=False)는 그 위치에 환경을 만들되 pip 준비를 생략합니다. 외부 패키지를 설치하지도, 현재 실행 중인 Python을 바꾸지도 않습니다.

os.path.join(folder, "pyvenv.cfg")는 설정 파일의 경로를 만듭니다. isfile()이 True이면 그 파일이 생겼다는 뜻입니다. with의 들여쓴 구간이 끝나면 이번 예제의 임시 폴더와 환경은 함께 정리됩니다.

앞의 터미널 명령으로 만든 지속적인 .venv를 사용하려면 macOS·Linux에서는 .venv/bin/python practice.py, Windows에서는 .venv\Scripts\python.exe practice.py처럼 실행 파일을 지정합니다. 아래의 임시 환경은 예제가 끝나면 없어지므로 이 경로로 재사용하지 않습니다.

Pythonenvironments.py
01import os02import tempfile03import venv04 05with tempfile.TemporaryDirectory() as folder:06    venv.create(folder, with_pip=False)07    configuration = os.path.join(folder, "pyvenv.cfg")08    print(os.path.isfile(configuration))

pip와 설치 범위 구별하기

pip는 선택한 Python이 사용할 외부 패키지를 설치하거나 설치 목록을 보여 주는 도구입니다. 프로젝트가 필요로 하는 외부 패키지를 의존성이라고 합니다. import는 설치된 모듈을 코드에서 가져오며, 인터넷에서 패키지를 설치하는 명령이 아닙니다.

아래 예제는 터미널 명령 세 개를 문자열로 담아 print로 보여 줄 뿐입니다. 출력된 명령을 실행하지 않으며 설치 목록도 조회하지 않습니다. 특히 앞의 with_pip=False 임시 환경에 pip가 준비됐다고 뜻하지 않습니다.

실제로 사용할 때 python -m pip는 python이 가리키는 실행 파일에 연결된 pip를 고릅니다. 가상 환경의 실행 파일 경로를 직접 적거나 환경을 활성화해 선택합니다. --version은 pip 버전과 위치, list는 설치 목록, freeze는 설치 버전을 기록할 텍스트를 보여 줍니다. 설치는 별도로 python -m pip install 패키지이름을 실행할 때 일어납니다. 이번 과정의 예제는 표준 라이브러리만 사용합니다.

Pythonenvironments.py
01commands = ["python -m pip --version", "python -m pip list", "python -m pip freeze"]02for command in commands:03    print(command)

실행 결과
