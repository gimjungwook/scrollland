이름이 유효한 범위 구별하기

함수 안에서 count를 2로 바꿨습니다. 그런데 함수 밖의 count는 여전히 10입니다. 어느 이름을 바꾼 걸까요?

함수 안 count = 2→바깥 count: 10

함수에는 호출할 때 실행하는 본문이 있습니다. 그 안에서 만든 이름과 바깥 이름이 항상 같은 대상을 뜻하지는 않습니다.

지역·전역 이름의 조회 위치를 구별하고, 반환된 함수 두 개가 각자의 count를 기억하는 흐름을 살펴봅니다.

읽고 나면지역·전역·바깥 함수 이름의 조회와 변경을 구별합니다.

함수 안 이름과 바깥 이름

이름 범위는 이름을 찾아 사용할 수 있는 영역입니다. 함수 안에서 대입한 지역 이름은 보통 그 함수 안에서만 유효합니다. 모듈의 바깥 수준 이름은 전역 이름입니다.

지역 이름이 있으면 같은 철자의 전역 이름보다 먼저 찾습니다. 아래 count = 2는 함수의 지역 이름을 만들며, 전역 count = 10을 바꾸지 않습니다.

같은 count라는 철자여도 여기서는 이름이 만들어진 곳이 다릅니다. local_count()의 return count는 함수 안의 2를 돌려주고, 마지막 print(count)는 함수 밖의 10을 읽습니다. 함수 안에서 숫자 10 자체를 2로 바꾼 것이 아닙니다.

Pythonscope.py
01count = 1002def local_count():03    count = 204    return count05 06print(local_count())07print(count)

전역 변경이 필요한지 먼저 판단하기

global은 이 함수에서 해당 이름을 전역 이름으로 다루겠다는 선언입니다. 아래 함수는 전역 calls의 값을 바꿉니다.

전역 상태에 의존하면 호출 순서에 따라 결과가 달라집니다. 보통은 값을 인자로 받고 반환하는 방식이 관계를 더 분명히 드러냅니다. 공유 상태가 필요한지 먼저 결정하세요.

record_call()을 한 번 호출하면 calls가 0에서 1로, 두 번 호출하면 1에서 2로 바뀝니다. global 선언 때문에 두 호출이 같은 전역 이름을 갱신합니다. 함수 안에 print()가 없으므로 두 호출 동안 출력은 없고, 마지막 print(calls)만 2를 출력합니다.

바깥 함수의 값을 기억하기

함수 안에서 또 다른 함수를 정의할 수 있습니다. 안쪽 함수가 바깥 함수의 지역 이름을 나중에도 사용하는 구조를 클로저라고 부릅니다. 이 예제의 add는 자신을 만든 make_counter() 호출의 count를 계속 사용합니다.

make_counter()를 호출하면 count=0을 준비하고 add 함수 자체를 돌려줍니다. return add에는 괄호가 없으므로 이때 count를 늘리지 않습니다. first()를 호출해야 그 add가 실행되어 count += 1을 수행합니다.

nonlocal count는 add 안의 새 지역 이름을 만드는 대신, 자신을 감싼 make_counter 호출의 count에 새 값을 연결하겠다는 뜻입니다. count += 1로 계산한 새 수를 그 count에 다시 대입합니다.

first와 second는 make_counter()를 각각 호출해 만들었습니다. 따라서 별도 count를 기억합니다. print(first(), first(), second())에서는 먼저 세 함수 호출을 왼쪽부터 계산합니다. 반환값 세 개가 모두 준비된 뒤 print()를 호출해 한 줄에 출력합니다.

first를 두 번 호출하면 second가 기억하는 count도 2가 될까요?
