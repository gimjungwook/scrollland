수학 도구로 결과 확인하기

0.1과 0.2를 더한 값이 화면에서 정확히 0.3으로 보이지 않습니다. 계산 결과를 어떤 기준으로 비교해야 할까요?

Decimal("0.1") + Decimal("0.2")→0.3

소수 계산의 작은 오차와 모듈 사용법을 배웠습니다. 가까운지 비교할지, 십진수를 정확히 다룰지에 맞춰 도구를 고릅니다.

근사 비교와 Decimal의 결과를 대조하고, 최솟값·평균·중앙값처럼 질문에 맞는 계산도 선택합니다.

내장 계산과 수학 함수 조합하기

min()과 max()는 가장 작은 값과 큰 값을, abs()는 부호를 제외한 크기를 구합니다. math.sqrt()는 제곱근이며 math.ceil()과 floor()는 각각 위쪽과 아래쪽 정수로 맞춥니다.

반올림과 올림은 다른 작업입니다. 2.1개 분량의 묶음을 담을 용기가 필요하다면 올림한 3개가 적절합니다. 계산 목적을 먼저 문장으로 적으세요.

ceil(2.1)은 담을 용기가 모자라지 않도록 3을, floor(2.9)는 2.9를 넘지 않는 정수 2를 고릅니다. ceil은 “소수 부분이 있으면 무조건 버린다”가 아니라 위쪽 정수를 고르는 함수입니다.

근사 비교와 정확한 십진수

float는 일부 소수를 이진수로 정확히 담지 못합니다. 이 예제에서 0.1 + 0.2는 0.30000000000000004입니다. 0.3과 아주 가깝지만 ==로 완전히 같다고 비교하면 거짓입니다.

math.isclose()는 두 값의 차이가 허용 오차 안에 있는지 묻습니다. True는 가깝다는 판정이며 원래 숫자를 고치거나 두 값이 완전히 같다는 뜻은 아닙니다. 측정값을 비교할 때는 문제에 맞는 허용 오차도 정해야 합니다.

Decimal은 십진수 계산용 자료형입니다. Decimal("0.1")처럼 글자로 적은 수에서 시작하면 float의 근사값을 먼저 거치지 않습니다. 아래 0.1과 0.2의 합은 정확히 0.3입니다. Decimal도 모든 계산을 무한히 정확하게 하지는 않으므로 일반적인 계산에서는 정밀도와 반올림 규칙을 함께 정합니다.

첫 출력 True와 다음 출력 0.3은 같은 방식으로 얻은 결과일까요?

자료의 대표값과 재현 가능한 무작위 선택

statistics.mean()은 평균을 반환합니다. median()은 정렬한 뒤 항목 수가 홀수면 가운데 값, 짝수면 가운데 두 값의 평균을 반환합니다. 큰 값 하나의 영향이 두 계산에서 다를 수 있으므로 대표값을 고르는 이유를 설명해야 합니다.

난수는 무작위처럼 생성한 수입니다. random.Random(7)처럼 시드를 고정하면 같은 입력 상태에서 실험을 재현할 수 있습니다. 시드는 생성기의 초기 상태를 정하는 값입니다. 아래 출력은 임의의 수 자체 대신 생성한 값이 범위 안인지 확인합니다.

counts의 합은 15이므로 평균은 15 / 3인 5입니다. 크기순으로 놓은 2·3·10의 가운데 값은 3입니다. 큰 값 10이 평균을 끌어올려 두 대표값이 달라집니다. 마지막 True는 뽑힌 값이 0 이상 1 미만인지 검사한 결과이며 난수 자체를 출력한 것이 아닙니다.

Pythonmath.py
01import statistics02import random03 04counts = [2, 3, 10]05print(statistics.mean(counts))06print(statistics.median(counts))07generator = random.Random(7)08value = generator.random()09print(0 <= value < 1)
