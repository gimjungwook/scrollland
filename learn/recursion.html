작은 같은 문제로 나누기

1부터 3까지의 합을 구하다가 1부터 2까지의 합을 같은 함수에 물으면, 답은 어떤 순서로 돌아올까요?

total_to(3)→3 + 2 + 1 + 0 = 6

함수 호출과 조건 분기를 배웠습니다. 함수가 더 작은 입력으로 자기 자신을 호출할 때는 멈출 조건부터 정해야 합니다.

0에서 끝나는 호출을 기준으로 기다리던 계산이 풀리는 순서를 추적하고, 같은 문제를 반복으로 푼 경우와 비교합니다.

읽고 나면재귀의 종료 조건·축소 단계·돌아오는 반환값을 추적합니다.

01

가장 작은 문제부터 정하기

재귀는 함수가 자기 자신을 호출하는 방식입니다. 1부터 n까지 더하는 문제는 n + “1부터 n-1까지의 합”으로 나눌 수 있습니다. n이 0일 때는 더할 수가 없으므로 0을 반환합니다.

종료 조건은 더 호출하지 않고 즉시 답을 내는 경우입니다. 아래 함수는 0 이상의 정수만 입력받는다고 정합니다. 음수를 넣으면 종료 조건 쪽으로 줄어들지 않으므로 이 계약을 지켜야 합니다.

Pythonrecursion.py
01def total_to(n):02    if n == 0:03        return 004    return n + total_to(n - 1)05 06print(total_to(0))07print(total_to(3))

호출이 쌓이고 답이 돌아오기

호출 스택은 아직 끝나지 않은 함수 호출들을 기억하는 구조입니다. total_to(3)은 total_to(2)의 답을 기다리고, 그 호출은 더 작은 문제의 답을 기다립니다.

0에서 종료하면 반환값이 역순으로 돌아옵니다. 0에 1을 더하고, 그 결과에 2, 그 결과에 3을 더하므로 6입니다. 아래 출력에서 내려가는 호출과 올라오는 답을 구별해 읽으세요.

0에 도달한 뒤 답은 어떤 호출부터 돌아올까요?

실행 후 관계와 값

total_to(3)
6 반환 · 모든 호출 종료

호출 방향: 3 → 2 → 1 → 0 · 반환 방향: 0 → 1 → 3 → 6

total_to(0)이 0을 반환하면 기다리던 total_to(1)이 1을, total_to(2)가 3을, total_to(3)이 6을 반환합니다.

마지막 6은 한 번에 나온 숫자가 아니라 작은 호출의 결과를 차례로 더한 합계입니다. 종료 조건이 없으면 이 반환 과정도 시작하지 못합니다.

03

반복이 더 알맞은 경우

Python은 너무 깊은 재귀 호출을 제한합니다. 단순히 긴 목록을 더하는 작업이라면 for나 sum()이 재귀 깊이에 의존하지 않아 더 알맞습니다.

재귀는 종료와 축소가 구조 자체를 잘 설명할 때 선택합니다. 아래 반복형은 같은 합을 누적값 하나로 계산합니다. 재귀가 늘 더 빠르거나 더 좋은 방식이라는 뜻은 아닙니다.

Pythonrecursion.py
01def total_to(n):02    total = 003    for value in range(1, n + 1):04        total += value05    return total06 07print(total_to(3))08print(total_to(100))

  1. 자기 자신을 한 번 더 호출하기만 하면 됩니다.

정답: 종료 조건과 그 조건으로 향하는 입력 변화가 필요합니다.작은 문제로 줄이고 가장 작은 문제에서 호출을 멈춰야 합니다.
