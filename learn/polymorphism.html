같은 요청을 여러 종류에 보내기

글, 리스트, 딕셔너리는 다른 자료인데 len()은 셋 모두에 답합니다. 같은 요청을 다른 객체가 받아도 될까요?

len("관찰") · len([4, 2])→모두 2

객체에 메서드를 만들었습니다. 호출하는 쪽이 기대하는 입력과 결과의 의미가 같다면 객체 종류가 달라도 같은 방식으로 요청할 수 있습니다.

여러 자료에 대한 len()부터 시작해, 공통 부모 없이도 같은 메서드 호출에 응답하는 객체를 비교합니다.

읽고 나면동일한 호출 계약을 여러 객체가 제공하는 다형성을 설명합니다.

먼저 익힐 개념 · 객체의 행동에 이름 붙이기

01

같은 함수가 여러 종류에 동작하기

다형성은 같은 연산이나 요청을 여러 종류의 객체에 적용할 수 있는 성질입니다. len()은 문자열의 글자 수와 리스트의 항목 수를 각각 구합니다.

출력 숫자가 같더라도 무엇을 세었는지 의미는 다릅니다. 공통 요청의 뜻을 “항목 수”처럼 설명할 수 있어야 다른 자료형에 사용한 결과도 이해할 수 있습니다.

Pythonpolymorphism.py
01print(len("관찰"))02print(len([4, 2]))03print(len({"숲": 4, "강": 2}))

상속 없이 같은 요청에 답하기

호출 계약은 객체를 사용하는 쪽과 정한 호출 방법과 결과의 약속입니다. 여기서는 인자 없는 summary()를 호출하면 설명 문자열을 돌려준다는 약속입니다.

덕 타이핑은 정확한 클래스 이름보다 필요한 동작을 제공하는지에 따라 객체를 사용하는 방식입니다. 두 클래스가 상속 관계가 아니어도 summary()를 제공하면 같은 반복에서 호출할 수 있습니다.

Pythonpolymorphism.py
01class BirdRecord:02    def summary(self):03        return "조류 4마리"04 05class WeatherRecord:06    def summary(self):07        return "날씨 맑음"08 09for record in [BirdRecord(), WeatherRecord()]:10    print(record.summary())

실행 결과

조류 4마리
날씨 맑음

반환 의미까지 같은 계약 유지하기

메서드 이름만 같다고 교체 가능한 것은 아닙니다. 한 객체는 문자열을 반환하고 다른 객체는 출력만 하고 None을 반환한다면 호출자가 기대한 결합이 깨집니다.

아래 render는 summary()가 문자열을 반환한다는 계약에 의존합니다. 각 클래스의 안쪽 구현은 달라도 이 계약을 유지하면 render를 고치지 않고 새 기록 종류를 추가할 수 있습니다.

Pythonpolymorphism.py
01def render(record):02    return "기록: " + record.summary()03 04class CountRecord:05    def __init__(self, count):06        self.count = count07    def summary(self):08        return f"{self.count}개"09 10class NoteRecord:11    def summary(self):12        return "수량 확인 전"13 14print(render(CountRecord(5)))15print(render(NoteRecord()))

실행 결과

기록: 5개
기록: 수량 확인 전

  2. 반드시 같은 부모 클래스만 상속합니다.
  3. 입력과 반환 의미를 포함한 호출 계약을 맞춥니다.

오답: 클래스 이름만 같습니다.이름이 아니라 실제 호출 가능 여부와 반환 의미가 중요합니다.

오답: 반드시 같은 부모 클래스만 상속합니다.상속 없이도 필요한 동작을 제공할 수 있습니다.

정답: 입력과 반환 의미를 포함한 호출 계약을 맞춥니다.같은 이름뿐 아니라 호출자가 기대하는 결과를 제공해야 합니다.
