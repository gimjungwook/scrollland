01

같은 함수가 여러 종류에 동작하기

다형성은 같은 연산이나 요청을 여러 종류의 객체에 적용할 수 있는 성질입니다. len()은 문자열의 글자 수와 리스트의 항목 수를 각각 구합니다.

출력 숫자가 같더라도 무엇을 세었는지 의미는 다릅니다. 공통 요청의 뜻을 “항목 수”처럼 설명할 수 있어야 다른 자료형에 사용한 결과도 이해할 수 있습니다.

Python 코드

Python 3.10+
print(len("관찰"))
print(len([4, 2]))
print(len({"숲": 4, "강": 2}))

예제 실행 결과

2
2
2

실행 흐름 살펴보기

검증한 예제의 상태를 순서대로 읽습니다.

  1. 1

    같은 호출

    모두 len()으로 크기를 묻습니다.

  2. 2

    종류별 처리

    각 객체의 크기 규칙에 따라 2를 반환합니다.

02

상속 없이 같은 요청에 답하기

호출 계약은 객체를 사용하는 쪽과 정한 호출 방법과 결과의 약속입니다. 여기서는 인자 없는 summary()를 호출하면 설명 문자열을 돌려준다는 약속입니다.

덕 타이핑은 정확한 클래스 이름보다 필요한 동작을 제공하는지에 따라 객체를 사용하는 방식입니다. 두 클래스가 상속 관계가 아니어도 summary()를 제공하면 같은 반복에서 호출할 수 있습니다.

Python 코드

Python 3.10+
class BirdRecord:
    def summary(self):
        return "조류 4마리"

class WeatherRecord:
    def summary(self):
        return "날씨 맑음"

for record in [BirdRecord(), WeatherRecord()]:
    print(record.summary())

예제 실행 결과

조류 4마리
날씨 맑음

실행 흐름 살펴보기

검증한 예제의 상태를 순서대로 읽습니다.

  1. 1

    첫 객체 요청

    summary()로 조류 설명을 받습니다.

  2. 2

    둘째 객체 요청

    같은 호출로 날씨 설명을 받습니다.

03

반환 의미까지 같은 계약 유지하기

메서드 이름만 같다고 교체 가능한 것은 아닙니다. 한 객체는 문자열을 반환하고 다른 객체는 출력만 하고 None을 반환한다면 호출자가 기대한 결합이 깨집니다.

아래 render는 summary()가 문자열을 반환한다는 계약에 의존합니다. 각 클래스의 안쪽 구현은 달라도 이 계약을 유지하면 render를 고치지 않고 새 기록 종류를 추가할 수 있습니다.

Python 코드

Python 3.10+
def render(record):
    return "기록: " + record.summary()

class CountRecord:
    def __init__(self, count):
        self.count = count
    def summary(self):
        return f"{self.count}개"

class NoteRecord:
    def summary(self):
        return "수량 확인 전"

print(render(CountRecord(5)))
print(render(NoteRecord()))

예제 실행 결과

기록: 5개
기록: 수량 확인 전

실행 흐름 살펴보기

검증한 예제의 상태를 순서대로 읽습니다.

  1. 1

    요청

    render가 객체의 summary를 호출합니다.

  2. 2

    결합

    반환 문자열에 기록:을 붙여 돌려줍니다.

원할 때 확인하세요

코드를 읽고, 한 번 예측하기

두 객체를 같은 summary() 호출로 사용하려면 무엇을 맞춰야 하나요?

정답과 모든 선택지의 해설 읽기
  1. 오답: 클래스 이름만 같습니다.

    이름이 아니라 실제 호출 가능 여부와 반환 의미가 중요합니다.

  2. 오답: 반드시 같은 부모 클래스만 상속합니다.

    상속 없이도 필요한 동작을 제공할 수 있습니다.

  3. 정답: 입력과 반환 의미를 포함한 호출 계약을 맞춥니다.

    같은 이름뿐 아니라 호출자가 기대하는 결과를 제공해야 합니다.

기억할 내용

같은 요청에 같은 의미의 결과를 제공하면 여러 종류를 같은 흐름에서 사용할 수 있습니다.
