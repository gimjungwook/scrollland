# 레슨에서 관찰할 변화와 설명 기준

작은 도입 그림이나 강조 효과가 있다는 사실만으로 레슨의 설명이 충분하다고 판정하지 않습니다. 제작자는 레슨의 학습 목표에서 초심자가 혼동할 지점을 찾고, 어떤 예제의 어느 중간 과정을 보면 그 혼동을 풀 수 있는지 기록합니다. 선택한 구간은 관찰 질문 → 사전 설명 → 스크롤로 살펴보는 변화 → 결과 해석으로 이어집니다.

## 이번에 바로잡은 판단

이전 구성은 본문 시각화가 14개 레슨에만 있었고 다른 30개 레슨에는 최종 코드와 결과를 비교하면 충분하다고 기록했습니다. 첫 레슨에서도 주석을 건너뛰는 과정, 계산과 출력의 차이, 출력이 쌓이는 순서를 학습자가 추론해야 했습니다. 도입 연출과 기술 검사 통과를 이 설명 공백의 해소 근거로 사용한 판단을 철회합니다.

이번 원고에서는 레슨별로 실제로 관찰할 과정을 선정했습니다. 전체 레슨을 확인하되 모든 절을 움직이는 무대로 바꾸지는 않습니다. 정의·사용 조건·추가 예제·확인 문항·요약은 계속 읽는 본문으로 남깁니다. 장면 수는 저작 결과이며 새 레슨을 추가할 때 채워야 하는 장식 할당량이 아닙니다. 레슨별 질문과 선정 이유는 [콘텐츠 선택 기록](content-presentation.md)에서 확인합니다.

## 원고 작성

- 처음 쓰는 용어는 학습자가 이미 아는 상황이나 짧은 예제에 연결해 설명합니다. 여러 정의를 한 문장에 압축하지 않습니다.
- 예제 앞에는 입력과 목표를, 뒤에는 결과가 나온 이유와 자주 생기는 오해를 적습니다.
- 각 관찰 단계는 현재 처리 중인 코드 줄, 그 시점의 값과 관계, 그때까지 생긴 출력, 이 상태가 된 이유를 함께 제시합니다. 출력은 해당 `print`를 처리한 단계에서만 추가합니다.
- 단계는 학습 설명 단위입니다. Python의 모든 내부 명령이나 CPU 시간을 재현한다고 주장하지 않습니다. 비교 자료는 실행 중인 메모리 그림과 구별합니다.
- 원본과 복사본, 문자열과 숫자, 함수 정의와 호출, 반환과 출력처럼 혼동하기 쉬운 개념은 구체적인 예제 값으로 비교합니다.
- 도입 그림은 주제 소개, 문구 효과는 문맥 강조, 본문 시각화는 특정 과정 관찰이라는 서로 다른 목적을 가집니다. 하나를 넣었다는 이유로 다른 설명을 생략하지 않습니다.

## 표시와 조작

학습자는 레슨 안에서 스크롤합니다. 관찰 구간에서는 코드·그림·출력·단계 설명이 화면 안에 함께 머물며 같은 진행 위치로 갱신됩니다. 역스크롤하면 같은 값과 선택을 복원합니다. 마지막 관찰 거리의 10%에서는 완성된 결과를 유지합니다. 레슨 끝에서 다음 페이지로 자동 이동하지 않습니다.

그림의 종류도 설명할 관계에 맞춥니다. 병렬 비교에는 연속 실행 화살표를 붙이지 않습니다. 문자열 슬라이스는 `sequence` 도식으로 각 위치와 글자를 고정하고 선택된 위치만 강조합니다. 이 도식의 `nodes[].active`는 선택 여부를 나타내는 불리언이며, 글자가 없어지거나 원본이 바뀌는 연출로 사용하지 않습니다. 색만으로 선택을 구별하지 않도록 “선택” 표기도 함께 제공합니다.

화면이 낮거나 움직임 줄이기를 사용하거나 JavaScript를 사용할 수 없으면 코드·출력·각 단계 설명·선택 표시를 순서 있는 정적 자료로 읽습니다. 효과가 없더라도 내용은 사라지지 않습니다.

## 검증과 완료 표현

각 레슨에서 시작·중간·완성·역방향의 실제 표시를 확인합니다. 진행률 변화만 확인하지 않고 활성 코드, 보이는 값, 누적 출력, 선택 범위, 화면 이탈과 겹침을 점검합니다. Python 예제 실행 결과와 설명용 중간 상태의 검토를 구별합니다.

자동 검사는 데이터 누락·잘못된 참조·회귀를 찾는 수단입니다. 자동 검사 통과나 제작자의 화면 검토를 학생이 이해했다는 증거로 쓰지 않습니다. 실제 실시한 화면 크기·표본·정적 대체 검사와 미실시 사항은 [구현 검증 기록](verification.md)에 남깁니다.
