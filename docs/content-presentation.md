# 본문과 연출의 콘텐츠 선택 기록

2026-09-23 기준의 콘텐츠 선택 기록입니다. ScrollLand는 본문을 계속 읽는 흐름을 기본으로 두며, 관계나 실행 순서를 같은 자리에서 따라가는 편이 이해에 도움이 되는 구간에 시각화를 사용합니다. 코스와 레슨은 주제를 소개하는 상징 그림과 제목으로 시작합니다. 본문 문구의 효과는 문맥상 강조·놀라움·작은 축하를 위한 표현으로 별도 지정합니다. 모든 구간의 학습 내용을 애니메이션으로 만들거나 효과가 끝날 때까지 다음 글을 기다리게 하지 않습니다.

## 유지한 교육 범위

8개 코스·44개 레슨과 기존 135개 코드 예제의 코드·예상 출력·제공 입력·파일 자료를 유지했습니다. 기존 본문 문장도 순서대로 보존했으며 일부 표현만 구조화된 굵게 표시·효과로 지정했습니다. 목표·선행 개념·문항·출처는 바꾸지 않았습니다.

원고를 검토한 현재 구성은 읽기 구간 127개, 시각화 구간 14개입니다. 읽기 구간 중 6개는 코드나 그림 없이 글로만 구성했고, 필요한 정적 비교 자료 39개를 남겼습니다. 변화 전후를 화면 안에서 비교할 수 있도록 선택한 14개 시각화 모두에 관찰 중 고정 표시를 지정했습니다. 일반 본문과 정적 예제 127개 구간은 고정하지 않습니다. 이 수치는 선택 결과이며 이후 콘텐츠의 최소 개수·비율·통과 기준이 아닙니다. 135개 예제와 시각화의 수는 서로 다른 값입니다.

기존의 반복적인 정적 요약 그림과 읽기 구간의 중복 단계 자료를 제거했습니다. 예제의 코드·출력·본문이 설명하던 교육 내용은 유지했습니다. 본문은 스크롤 진행률에 따라 교체하거나 숨기지 않습니다. 시각화 앞에는 관찰 질문, 뒤에는 해석 본문이 이어집니다.

## 코스와 레슨의 도입

8개 코스 모두에 주제별 상징 그림·두 줄 제목·상황·학습 결과 예고·구체적인 전후 자료를 작성했습니다. 44개 레슨 모두에는 질문·앞선 학습과의 연결·관찰할 결과·전후 미리보기를 넣었습니다. [도입 콘텐츠 기록](intro-content.md)은 코스별 장면과 레슨별 예제 근거를 설명합니다.

전체 문서는 코스 도입 뒤에 해당 레슨들을 배치하며, 첫 도입에 서비스 소개를 합쳤습니다. 개별 레슨 주소는 같은 레슨 도입을 제공하고 코스 전체 도입을 중복하지 않습니다. 도입 그림은 주제의 상징이며, 특정 코드의 단계별 실행을 재현하는 14개 시각화와 구별합니다.

도입은 스크롤 위치에 따라 제목과 그림의 배치가 달라지는 별도 연출입니다. 코스는 도입 전체가 화면에 들어가면 전체를, 그렇지 않으면 그림·캡션·전후 미리보기만 고정해 변화하는 모습을 관찰하게 합니다. 해당 영역도 화면에 담기지 않으면 완성된 정적 그림을 표시합니다. 고정 위치는 머리말 아래 12px이고, 관찰용 추가 거리는 화면 높이의 70%를 320~720px 범위로 제한합니다. 마지막 15% 거리에서 완성된 모양을 유지합니다. 작은 레슨 도입은 제목과 그림 영역의 위쪽이 화면 높이의 85%에서 45%로 이동하는 동안 연출하며 고정하지 않습니다.

제목·설명·미리보기는 처음부터 읽을 수 있고, 본문 숨김이나 시간 재생 완료 대기는 없습니다. 큰 제목과 그림 자체를 금지하지 않으며, 정적 표시에서도 같은 글과 완성된 그림을 남깁니다. 관찰 대상 없이 빈 공간만 늘리거나 본문 전체를 고정하는 구성은 사용하지 않습니다.

도입 8개·44개는 기존 읽기 구간 127개·시각화 구간 14개·본문 문구 효과 6개의 개수에 합산하지 않습니다. 도입을 보강하면서 기존 본문·예제·문항과 그 순서는 유지했습니다.

## 레슨별 판단

| 레슨 | 읽기와 연출을 선택한 이유 |
| --- | --- |
| 처음 실행하고 결과 읽기 (`run-python`) | 짧은 코드와 실제 출력의 줄 순서로 정의·실행·주석을 설명합니다. 첫 화면부터 본문에 도달하며 별도 학습 무대는 없습니다. |
| 값에 이름을 연결하기 (`variables`) | 이름·값·오른쪽 계산은 본문과 정적 예제로 읽습니다. 재대입 항목에서만 saved의 연결을 유지하며 birds의 연결이 바뀌는 모습을 추적합니다. |
| 같아 보이는 값 구별하기 (`data-types`) | 숫자와 문자열, 0과 None의 차이는 같은 위치에서 읽을 수 있는 정적 비교가 적합합니다. 형 변환도 코드·출력과 설명으로 확인합니다. |
| 수량과 나머지 계산하기 (`numbers`) | 연산 목적과 결과를 비교하는 것이 목표입니다. 몫·나머지와 괄호의 뜻은 정적 비교로 설명하고 근사값의 작은 차이는 문구에만 빛 효과를 둡니다. |
| 글의 위치와 표현 다루기 (`strings`) | 인덱스와 슬라이스 경계를 정적 자료로 계속 볼 수 있게 합니다. 출력 서식에 별도 시간 흐름을 만들지 않습니다. |
| 입력한 글을 정리하기 (`text-tools`) | 문자열을 정리하는 호출과 결과를 읽습니다. 나누기·중간 리스트·다시 잇기의 관계만 정적 비교로 덧붙입니다. |
| 입력을 받아 답 만들기 (`input-output`) | 제공한 입력과 표준 출력을 구별해 읽습니다. 브라우저에서 입력을 받거나 입력 대기를 연출하지 않습니다. |
| 조건을 참과 거짓으로 읽기 (`booleans`) | 각 질문이 참인지 거짓인지 코드와 출력에서 바로 대조할 수 있어 본문·정적 예제로 구성합니다. |
| 상황에 맞는 실행 경로 고르기 (`branching`) | 첫 if 예제에서 건너뛴 코드와 분기 바깥 복귀를 시각화합니다. elif·조건 표현식·match는 정적 예제로 확장합니다. 조건 검사·선택한 분기·바깥 복귀를 모두 볼 수 있도록 관찰 중 무대를 고정합니다. |
| 연산의 뜻과 우선순위 확인하기 (`operators`) | 값 비교·동일 객체·포함 여부는 정적 관계 비교로 구별합니다. 단락 평가와 비트 연산은 코드와 결과를 읽습니다. |
| 리스트의 순서와 항목 바꾸기 (`lists`) | 항목의 읽기·추가·삭제 결과가 짧은 코드에 직접 드러납니다. 변화를 보여준다는 이유만으로 모든 리스트 연산을 시각화하지 않습니다. |
| 리스트를 복사하고 정렬하기 (`list-transform`) | 공유 리스트의 항목 변경을 시각화해 재대입과 구별합니다. 별도 복사와 정렬은 정적 예제와 비교로 이어집니다. |
| 한 묶음의 의미를 고정하기 (`tuples`) | 정해진 역할, 풀어 받기, 새 튜플 만들기는 본문과 정적 예제로 설명합니다. |
| 중복과 공통 항목 찾기 (`sets`) | 집합 간 공통·차이의 공간적 비교는 정적 자료가 적합합니다. 중복 제거·고정 집합도 코드와 결과를 읽습니다. |
| 이름표로 값 찾기 (`dictionaries`) | 키 조회, 기본값, 갱신의 결과를 정적 예제로 읽습니다. 같은 개념을 움직이는 카드로 반복하지 않습니다. |
| 중첩된 기록 읽기 (`nested-data`) | 중첩 경로는 정적 자료로 먼저 읽습니다. 얕은 복사에서는 공유한 안쪽 리스트와 독립한 리스트를 시각화해 변경이 전해지는 경계를 추적합니다. |
| 모든 항목에 같은 작업 하기 (`for-range`) | 항목별 출력과 범위의 끝 경계는 정적 예제로 확인합니다. 같은 반복 원리를 다시 긴 고정 구간으로 만들지 않습니다. |
| 끝날 조건까지 반복하기 (`while-loops`) | 첫 예제에서 조건 검사와 누적값 변경을 시각화합니다. 그 뒤 누적 변수 분리와 종료 규칙은 본문·정적 예제로 읽습니다. |
| 건너뛸 때와 멈출 때 정하기 (`loop-control`) | continue 구간에서 누적값이 유지되면서 다음 항목으로 이동하는 경로를 시각화합니다. break·else는 정적 코드와 경로 비교로 구별합니다. |
| 필요한 값만 새 묶음으로 만들기 (`comprehensions`) | 일반 반복과 짧은 표기의 결과를 나란히 비교하는 것이 목표이므로 정적 코드·출력 비교로 구성합니다. |
| 계산에 이름을 붙여 재사용하기 (`functions`) | 정의와 호출을 구별하는 첫 예제에서 실행 위치의 이동·복귀를 시각화합니다. 인자·반환·출력의 구별은 본문과 정적 예제에 남깁니다. |
| 함수 입력의 규칙 정하기 (`arguments`) | 인자를 모으고 푸는 규칙과 위치·이름 제한을 정적 비교로 읽습니다. 기본값 객체를 공유하지 않는 방법은 코드로 확인합니다. |
| 이름이 유효한 범위 구별하기 (`scope`) | 지역·전역의 차이는 정적 비교로 읽습니다. 클로저 항목에서 별도 count 두 개와 호출 순서를 함께 추적합니다. |
| 필요한 값부터 하나씩 만들기 (`iterators-generators`) | 다음 항목과 소비의 뜻을 먼저 읽고 yield에서 멈춘 위치와 다음 요청의 재개를 시각화합니다. 제너레이터 식은 정적 예제로 연결합니다. |
| 짧은 계산을 함수에 전달하기 (`lambda`) | 짧은 함수 표기와 전달·정렬 기준·선택의 계약을 정적 예제로 읽습니다. 함수 호출 자체가 있다는 이유로 무대를 추가하지 않습니다. |
| 작은 같은 문제로 나누기 (`recursion`) | 종료 조건을 먼저 읽고 호출이 쌓였다가 반환되는 지점에서만 시각화합니다. 반복으로 바꾸는 선택은 뒤의 본문으로 돌아와 비교합니다. |
| 함수 앞뒤에 공통 작업 붙이기 (`decorators`) | 감싼 함수를 준비하는 시점과 실제 호출의 앞뒤 작업을 시각화합니다. @ 표기와 wraps의 역할은 정적 예제로 읽습니다. |
| 모듈을 불러와 연결하기 (`modules`) | 가져올 파일과 실행 경계를 정적 자료로 비교합니다. 코드 구성의 규칙을 읽는 데 고정 무대는 필요하지 않습니다. |
| 프로젝트마다 도구 환경 나누기 (`environments`) | 레슨 전체를 본문과 정적 예제로 구성합니다. 가상 환경 생성, 실행할 Python 선택, pip 명령의 범위를 문장과 비교 자료로 구별할 수 있습니다. |
| 날짜를 값으로 계산하기 (`dates`) | 달력 계산 결과와 시간대 해석 조건을 정적 예제로 읽습니다. 시간의 주제라고 해서 시간에 따라 움직이는 화면을 만들지 않습니다. |
| 수학 도구로 결과 확인하기 (`math`) | 계산 목적과 반환값을 읽고 근사 비교·십진수의 차이는 정적 비교로 표시합니다. |
| 일정한 글 패턴 찾기 (`regex`) | 검색 범위와 그룹의 뜻을 코드·정적 비교로 설명합니다. 문자열 치환 결과도 그대로 남겨 대조하게 합니다. |
| 다른 도구에서도 읽을 수 있는 기록 만들기 (`json-data`) | 직렬화·역직렬화와 자료형의 변화는 코드·결과·정적 비교로 읽습니다. 변환 단계마다 스크롤 공간을 늘리지 않습니다. |
| 데이터와 행동을 객체로 묶기 (`objects`) | 정의, 초기화, 개별 객체의 상태를 정적 예제로 읽습니다. 객체 둘의 속성 차이는 정적 비교로 확인합니다. |
| 속성의 공유와 변경 규칙 정하기 (`attributes`) | 개별 속성·유효값 규칙은 본문으로 읽습니다. 클래스 속성을 개별 속성으로 가리는 항목에서만 무대를 고정해 first의 경로와 유지되는 공통 값을 비교합니다. |
| 객체의 행동에 이름 붙이기 (`methods`) | 인스턴스·클래스·정적 메서드가 무엇을 받는지 정적 비교로 구별합니다. |
| 공통 행동을 이어받아 바꾸기 (`inheritance`) | 상속·부모 초기화·재정의는 호출 코드와 출력에 맞춰 설명합니다. 이미 배운 호출 이동을 매 항목 다시 시각화하지 않습니다. |
| 같은 요청을 여러 종류에 보내기 (`polymorphism`) | 서로 다른 객체가 지키는 호출 계약을 정적 예제로 비교합니다. 종류 수만큼 무대를 늘리지 않습니다. |
| 기본 연산과 객체 연결하기 (`special-methods`) | 기본 연산과 연결되는 메서드를 읽고 실제 출력과 반환 의미를 비교합니다. 표기의 특이함만으로 별도 애니메이션을 추가하지 않습니다. |
| 관련된 작은 자료형을 안에 두기 (`nested-classes`) | 이름의 경로와 실제 객체 연결을 정적 자료로 비교합니다. 중첩 정의를 자동 결합으로 오해하지 않도록 본문에 조건을 남깁니다. |
| 예외를 구별해 처리하기 (`exceptions`) | 첫 예제에서 변환 실패·처리·바깥 복귀를 시각화합니다. 정상 경로, 정리, 직접 발생시킨 예외는 정적 예제로 확장합니다. |
| 저장된 파일에서 기록 읽기 (`read-files`) | 경로·인코딩·파일 내용은 먼저 읽습니다. 한 줄씩 읽는 구간에서 읽기 위치와 출력·닫힘을 함께 추적한 뒤 해석 본문으로 돌아옵니다. 문자·바이트 비교는 정적입니다. |
| 파일을 만들고 안전하게 정리하기 (`write-files`) | 생성·추가·덮어쓰기·삭제의 경계와 예제 경로를 문장으로 남깁니다. 이전·새 파일 내용은 정적 비교로 충분히 확인할 수 있습니다. |
| 관찰 기록을 읽고 요약해 저장하기 (`final-project`) | 여러 규칙이 연결된 긴 코드를 계속 읽을 수 있어야 하므로 정적 예제로 구성합니다. 결과 확인 뒤 짧은 문구 주변에만 축하 효과를 두며 학습 이수로 판정하지 않습니다. |

## 채택한 시각화

아래 표의 상태 시작 위치는 학습 진행률 0~1을 기준으로 합니다. 실제 관찰용 스크롤 진행률을 `p`라고 할 때 학습 진행률은 `p / 0.9`를 0~1 범위로 제한한 값입니다. 원고의 마지막 위치 `1`은 실제 거리의 90% 지점에 해당하며, 남은 10% 거리 동안 완성 상태를 유지한 뒤 고정을 풉니다. 선택한 14개 시각화는 코드·값·출력·관계를 같은 자리에서 비교하는 동안 무대를 화면에 유지하도록 pin을 true로 지정합니다. scrollDistance는 각 시각화의 관찰에 사용할 추가 스크롤 거리의 svh 단위 값입니다. 읽기 구간에는 이 높이나 고정을 적용하지 않습니다.

분기와 속성 구간도 상태 변화 자체를 관찰해야 하므로, 짧다는 이유로 화면 밖을 지나가면서 연출을 마치게 하지 않습니다. 화면이 낮아 무대 전체를 담지 못하면 동적 무대를 숨기고 순서 있는 정적 상태 자료로 대체해 모든 상태를 읽게 합니다. 스크롤 거리·상태 위치는 각 예제에 맞춰 정하며, 실제 화면에서는 시작 상태·각 중간 상태·최종 상태를 볼 수 있는 위치와 역방향 복원을 확인해야 합니다.

## 본문 강조 서식

굵게 표시만 있는 원고는 정적으로 표시합니다. 지정한 여섯 문구에만 아래 효과를 적용합니다. 효과 정보에는 목적·시작과 종료 기준·진입 방식·반복 진입·구간 이탈·초기 진입 규칙을 함께 적습니다. 현재 여섯 문구는 화면 높이의 85% 위치에서 35% 위치까지를 효과 구간으로 지정했습니다. 진입 재생 시간은 0.85~1.1초이며, 진행률 연결 효과의 위치는 경과 시간이 아닌 스크롤 위치로 정합니다. 시간 재생은 문구의 장식 표현에만 사용하며 다음 학습 내용으로 자동 진행하지 않습니다.

진행률 연결 효과는 같은 스크롤 위치에서 같은 표현을 표시합니다. 진입 재생 효과는 해당 문구에 진입할 때 지정한 시간 동안 재생합니다. 초기 위치 skip은 화면을 처음 구성할 때 문구가 효과 구간 안에 있거나 이미 지나간 위치여도 장식 재생을 시작하지 않습니다. 그 뒤 다시 진입했을 때의 재생은 once·repeat 규칙을 따릅니다. 재진입 repeat도 문구에 머무는 동안 자동 반복하는 뜻이 아닙니다. 효과는 글자를 가리거나 줄 배치를 바꾸지 않으며 움직임 줄이기·연출 실패에서는 원래 문구와 정적 서식을 남깁니다.

## 자료 계약과 확인 범위

- 기존 예제의 식별자는 원래 예제 순서에 따라 `<slug>-scene-<번호>`로 고정했습니다. 새 글 구간을 앞에 넣어도 기존 예제 주소는 바뀌지 않습니다.
