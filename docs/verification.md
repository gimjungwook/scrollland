## 스크롤 중 관찰 가능성 수정 검증

사용자 검토에서 장면이 화면을 벗어나는 동안 연출도 진행되어 변화를 관찰하기 어렵다는 문제가 확인됐습니다. 기준본 `76bc1a4`의 검사는 위치별 상태 변화와 제목 표시를 확인했지만, 진행 내내 변화하는 그림·설명이 화면 안에 남는지는 완료 조건에 포함하지 못했습니다. 아래 기준본의 통과 기록을 이 요구의 충족 근거로 사용하지 않습니다.

코스 도입은 전체가 화면에 들어오면 전체를, 그렇지 않으면 그림·캡션·전후 미리보기만 화면에 유지합니다. 작은 레슨 도입은 계속 읽으면서 제목이 화면을 벗어나기 전에 마칩니다. 관찰 대상으로 선택한 학습 시각화 14개는 모두 고정을 요청합니다. 화면 안에 학습 무대 전체가 들어오지 않으면 동적 무대를 숨기고 순서 있는 정적 자료만 표시합니다. 일반 읽기 127개 구간은 고정하지 않습니다.

코스 도입은 관찰 거리의 85%, 학습 시각화는 90%에서 완성 상태에 도달합니다. 나머지 거리에서 결과를 확인한 뒤 자연스럽게 다음 본문으로 이동합니다. 스크롤 잠금·강제 스냅·시간 대기·자동 학습 이동은 없습니다.

## 구현 범위

8개 코스·44개 레슨과 독립 실행 예제 135개를 보존했습니다. 원고는 읽기 127개 구간과 시각화 14개 구간으로 구성했습니다. 읽기 중 6개는 글만 있으며, 정적 비교 자료 39개와 명시한 문구 효과 6개를 사용합니다. 이 개수는 원고별 선택 결과이며 제작 할당량이 아닙니다. [구간별 선택 근거](content-presentation.md)와 [교육 범위](curriculum-coverage.md)를 함께 확인할 수 있습니다.

본문·정적 예제·확인 문항은 일반 문서 흐름에 남습니다. 선택한 시각화에만 상태 계산을 연결하며, 문구 효과는 별도 자료와 실행 경로를 사용합니다. 필수 학습 입력은 스크롤이고 목차·출처 링크는 선택 탐색입니다. JavaScript가 없어도 학습 자료가 HTML에 들어 있습니다.

| 연출 파일 실패 | GSAP·ScrollTrigger 파일만 차단하고 다시 읽어 같은 정적 자료와 모든 본문·근거 유지 확인. 검사 후 차단 해제 |

자동 검사는 교육적 타당성이나 학생의 이해도를 증명하지 않습니다. DOM 대역 검사와 실제 브라우저 검사를 구분했습니다. 상태 자료의 전수 의미 검증은 자동 검사이며, 위 배치 검사는 명시한 표본 위치의 실측입니다.

## 검수 중 고친 문제

- 읽기 구간에 예제·도식·실행 단계 개수를 강제하던 계약, 모든 구간 고정, 본문 교체, 긴 정답 공개 구간을 제거했습니다.
- 긴 코드 전체 높이가 무대를 늘리던 문제를 고쳤습니다. 코드 표시 위치는 해당 실행 줄을 따라가며 별도 내부 조작을 요구하지 않습니다.
- 동일한 이름·객체의 자리를 시각화 전체에서 유지하고, 새 상태 문장 아래에 이전 값·연결이 남던 전환 불일치를 제거했습니다.
- 정적 대체본의 중복 코드 줄이 강조·위치 계산에 섞이지 않도록 범위를 제한했습니다.
- 긴 리스트 값의 과도한 확대와 낮은 화면의 도식 영역 이탈, 정적 코드 줄 번호의 부족한 대비를 보정했습니다.
- 초기 주소 이동을 마친 뒤 문구 효과를 준비해 최초 표시 시 재생하지 않는 설정을 지킵니다. 단어 효과 실패는 원문을 남기고 구현 오류만 기록합니다.
- 고정하지 않는 시각화의 진행 거리를 아래 정적 설명의 높이와 분리했습니다.
- 문구 효과의 입자를 읽기 영역과 화면 안에 제한하고, 종료·취소된 투명 입자의 변형 좌표를 제거했습니다. 360×800 새 방문에서 폭죽·색종이 각각 10개 입자가 나타나는 동안 75프레임씩 검사해 가로 넘침 0px를 확인했습니다.

## 미실시 항목과 공개 상태

640×450 검사는 1280×900 화면을 200% 확대했을 때와 같은 CSS 배치 폭·높이를 점검한 것입니다. 브라우저 메뉴의 실제 200% 확대와 화면 낭독기 전체 흐름, Safari·Firefox, 물리 휴대전화, 저성능 기기의 성능은 별도 검사가 필요합니다. 이번 결과로 모든 브라우저의 접근성 인증을 주장하지 않습니다.

GitHub 소스 공개와 운영 웹사이트 배포는 별개입니다. 이 변경은 공개 브랜치와 검토 요청으로 전달하며 main 병합·운영 배포·교수 승인·학생 학습 효과 검증을 완료로 기록하지 않습니다. GitHub Actions는 Python 3.10·3.14에서 같은 자동 검사를 실행합니다. 특정 공개 커밋의 통과 여부는 해당 커밋의 Actions 결과로 확인해야 합니다.

## 재현

`npm run build` 후 `npm run validate`를 실행합니다. 스타일·실행 코드를 바꾸면 대표 화면과 해당 접근성 경로를 실제 브라우저에서도 다시 확인합니다. 개발 서버는 `python3 -m http.server 8765 --bind 127.0.0.1`로 시작합니다. 이 서버의 기본 오류 화면은 제품의 404와 다르므로, 사용자 정의 404를 제공하는 검사 서버나 실제 정적 호스팅에서 오류 경로를 별도로 확인합니다.
