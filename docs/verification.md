## 재시도 성공 시 초점 처리 수정

요청 중 재시도 버튼은 `aria-disabled`와 중복 요청 차단으로 비활성 상태를 알리며 키보드 초점은 유지합니다. 성공 시점에도 버튼에 초점이 있으면 안내문을 “답변 확인과 단계 강조를 사용할 수 있습니다.”로 바꾸고, `tabIndex = -1`과 `focus({ preventScroll: true })`로 안내문에 초점을 옮긴 다음 버튼을 숨깁니다. 요청 중 사용자가 다른 곳으로 초점을 옮겼거나 처음부터 정상 로딩된 경우에는 초점을 옮기지 않고 안내를 숨깁니다. 재실패하면 버튼이 다시 사용 가능한 상태로 남습니다.

이 수정 후 `npm run build`와 `npm run validate`를 실행했습니다. 자동 검사 17개, 생성물·내부 파일 링크 검사, Python 예제 135개 실행·출력 비교가 통과했습니다. 새 검사 4개는 초기 성공, 버튼 초점 유지 상태에서 성공, 요청 중 다른 곳으로 초점 이동 후 성공, 재실패 후 다시 성공하는 비동기 제어 흐름을 확인합니다. DOM 대역을 사용하므로 네이티브 키보드 초점·스크롤 동작의 증거는 아닙니다.

실제 Chromium 브라우저에서도 4초 지연 응답을 사용해 확인했습니다. Enter로 재시도하면 요청 중 버튼에 초점이 유지되고, 성공 후 안내문에 초점이 옮겨지며 스크롤 위치는 546.5px로 동일했습니다. 이어 Tab을 누르면 첫 예제 코드로 이동했습니다. 별도 재시도에서 요청 중 Tab으로 코드 영역에 이동한 초점은 성공 후에도 유지됐습니다. 반복 실패 시 버튼에 초점이 남고 다시 사용할 수 있었으며, 최초 정상 로딩은 문서 본문 초점과 맨 위 위치를 유지했습니다.

## 내용·디자인 검토

교육 콘텐츠는 앞뒤 22개 레슨씩 서로 다른 검토자가 설명·코드·출력·도식·실행 상태·문항을 대조했습니다. 1차의 19개 지적을 반영한 뒤 전체를 다시 읽었습니다. 2차의 미소개 용어 한 문장과 조사 오타 한 문장도 수정했습니다. 코스·레슨의 경계와 예제 문장은 직접 작성했습니다.

디자인은 [18개 공식 참고 자료](design-references.md)를 조사하고 그중 15개 화면을 직접 확인했습니다. 연속 읽기, 코드와 결과의 근접 배치, 낮은 강도의 강조를 채택했습니다. 설명을 읽기 위해 클릭·문항 응답·연출 종료를 기다릴 필요가 없습니다.

## 아직 검증하지 않은 범위

- 실제 휴대전화·태블릿, Safari·Firefox, 화면 낭독기 전체 사용 흐름은 확인하지 않았습니다. 위 화면 크기는 브라우저의 화면 크기 모의 설정입니다.
- 200% 확대에 해당하는 CSS 화면 크기 640 × 450 / DPR 2의 재배치에서 가로 넘침이 없었습니다. 인앱 브라우저의 실제 확대 명령은 적용되지 않아, 이를 실제 브라우저 200% 확대 통과로 기록하지 않습니다.
- HTTPS 운영 배포와 캐시 없는 네트워크·CPU 지연 조건의 첫 화면 3초 목표는 아직 측정하지 않았습니다. 로컬 화면 검사는 이 성능 측정을 대신하지 않습니다.
- GitHub 코드 공개, 웹사이트 운영 배포, 교육 내용 승인, 학생의 학습 효과 검증은 서로 다른 상태입니다. 학생을 대상으로 한 검증은 수행하지 않았습니다.
- 로컬 확인 환경과 GitHub의 Ubuntu 확인 환경 이외의 운영체제·Python 버전 조합은 별도 실행하지 않았습니다.

## 반복 확인 방법

`npm run validate`는 자동 검사·생성물 일치·예제 실행을 차례로 수행합니다. 콘텐츠를 바꾸면 먼저 `npm run build`로 생성물을 갱신합니다. 새로운 배포에서는 실제 호스팅 경로의 정상 주소와 없는 주소, JavaScript 비활성 읽기, 네트워크 실패 복구를 다시 확인합니다.
